# 将确认后的页面观测物化为独立 Feed Entry

阶段 5A.3 在 `feed-supplier` 中保存页面来源、最近接受的基线、待确认候选和不可变变化事件。页面来源使用
`pagechange://<source-uuid>` 作为稳定 Feed 身份；目标网页 URL、抽取规则和调度状态只存在供给端。

页面基线初始为空。第一次成功取得非空规范化内容时立即发布第一条具有新 GUID 的页面消息，并把该内容接受
为基线。后续不同指纹先保存为候选，默认五分钟后再次观测到相同候选才发布；恢复基线时丢弃候选，候选再次
变化时重新开始确认。空内容不建立基线，也不发布消息。

页面 HTTP 获取、SSRF 校验、内容抽取、条件请求、调度、失败退避和候选确认全部属于供给端。Folo 核心读取
供给端已经物化的 RSS，不在 Feed 请求过程中访问目标网页。普通 HTTP/HTTPS RSS 和 `rsshub://` 的路由、
调度和导入语义保持不变。页面事件和接受新基线在同一数据库事务中提交，事件表拒绝更新或删除。

第一版只支持服务端可直接访问的公开 HTML/文本页面和 CSS 选择器，不支持浏览器渲染、登录 Cookie、截图
差异、AI 语义差异或外部通知。页面 Entry 导入核心后，可以正常进入既有 Action 和自主 AI 处理流水线。
