# 经供给端用官方 Folo 账号获取指定来源

## 背景

阶段 5A 完成后，订阅入口已经统一到自有后端：标准 RSS 由核心直连，`rsshub://`、`pagechange://`、
`weblist://` 由供给端提供。剩下的缺口是自建 RSSHub 抓不到或抓不稳的路由（典型是 X、Telegram 等需要
凭据和反爬维护的平台）。应用所有者在官方 Folo 有账号，官方托管的 RSSHub 能稳定取得这些来源。

主方案的阶段 5B 已经确定方向：官方只作为获取提供方，按单个 Feed 授权，在官方账号中建立影子订阅，
取回的 Entry 转成内部契约后由自有服务保存。主方案写于供给端拆分（ADR-0025、ADR-0026）之前，没有说明
适配器放在哪个服务、获取关系存在哪个库。本决策确定阶段 5B 第一刀的落点和范围。

ADR-0033 解决的是相反方向：把供给端的来源交给官方 Folo 读取。两者互不替代。

## 决策

### 适配器属于供给端

官方账号凭据、影子订阅、获取关系和对官方接口的全部调用都在 `apps/feed-supplier`。核心仍然只经内部通道
取得标准 RSS，不保存官方凭据，不持有官方资源 ID，也不直接访问官方接口。这延续 ADR-0025（核心不访问
非 Feed 平台）和 ADR-0026（凭据与来源配置不进入核心数据库）。

### 逻辑地址不变，提供方由绑定决定

第一刀只支持 `rsshub://` 来源。核心保存的逻辑地址不变；供给端为某个逻辑地址保存一条**获取绑定**，
声明它由 `folo_official` 提供。`GET /v1/feeds/rsshub` 先查绑定：

- 绑定为 `active`：从官方读取该 Feed 的 Entry，渲染成 RSS 返回。
- 绑定为 `pending` 或 `failed`：返回 503，不回退到自建 RSSHub。
- 没有绑定，或绑定已进入 `pending_deletion`：走现有的自建 RSSHub 路径。

因此切换提供方不改变本地 Feed、Subscription 和 Entry 的身份，核心不需要数据库迁移。实例只有一个
所有者，逻辑地址与本地订阅一一对应，所以绑定以逻辑地址为键，不引用核心的订阅 ID。

带秘密查询参数的地址，以及路由实例绑定了供给端凭据的地址，不能建立官方绑定：否则会把自有凭据交给官方。

### 官方账号关联

- 实例最多关联一个官方账号。凭据是所有者显式提供的官方会话令牌，用现有凭据密钥加密保存
  （ADR-0026），任何读取接口都不返回原文。供给端不读取浏览器 Cookie。
- 官方接口只接受会话 Cookie，不接受 Bearer（5B.0 已验证）。供给端把所有者提供的令牌作为会话 Cookie 发送；
  按主方案，Cookie 属于兼容凭据，需要记录获得时间、最近验证时间和过期时间，并在到期前提醒重新关联。
- 关联和每次校验都调用官方的会话接口，记录官方用户 ID、套餐角色和 RSSHub 订阅额度。
- 官方返回未授权时，账号立即标记为 `auth_invalid`，此后所有官方读取直接失败，不再发出请求，直到所有者
  重新关联。
- 关联、绑定和解绑只经 `ADMIN_TOKEN` 管理接口和命令行提供。令牌属于秘密，按 ADR-0032 的原则，第一刀
  不交给核心代理，也不提供前端入口。

### 影子订阅

- 优先接管官方账号中已有的订阅：这是所有者现有来源的主要情形，不产生任何官方写操作。
- 官方账号中没有该订阅时，建立绑定会订阅同一个 `rsshub://` 地址并保存官方 Feed ID。套餐允许时标记为
  私有订阅；套餐不允许时（`free` 套餐如此），只有所有者对该来源明确同意公开订阅后才创建。
- 创建前核对官方的 RSSHub 订阅额度，额度不足时拒绝，不向官方发请求。
- 官方账号里已经存在该订阅时，绑定记为 `adopted`，否则记为 `created`。供给端只会删除自己创建的影子
  订阅，从不删除、修改所有者原有的官方订阅。
- 解绑后绑定进入 `pending_deletion`，七天后由清理任务删除 `created` 的影子订阅；七天内重新绑定则复用。
  已导入自有服务的 Entry 不受影响。
- 供给端对官方账号的写操作仅限创建和删除影子订阅。不上传本地订阅清单、已读、收藏、Action、评估结果、
  画像或 Taxonomy，也不在官方账号中标记已读。

### 读取与渲染

- 每次读取取该 Feed 最新的一页 Entry（含正文），渲染为 RSS 2.0。`guid` 使用官方返回的源 GUID，而不是
  官方 Entry ID，使日后切换到自建 RSSHub 时核心能按 GUID 去重。
- 渲染结果进入现有的 Redis 响应缓存和请求合并（ADR-0029），并有独立于自建 RSSHub 的限流和并发上限。
  `ETag` 由渲染结果的摘要生成，支持 `If-None-Match`。
- 供给端不保存官方 Entry。官方 Entry ID 与本地 Entry 的映射第一刀不建立。
- 官方响应按用到的字段做严格校验；形状不符时该次读取失败，不把未知数据传给核心。

### 失败时不自动切换

第一刀没有自动降级。官方读取失败时供给端返回明确的错误码，核心沿用现有的每源退避、获取诊断和告警；
已导入的 Entry 保持可读。切回自建 RSSHub 是所有者的显式操作（解绑）。

### 与私有 RSS 公开通道互斥

已绑定官方获取的来源不能签发公开链接（ADR-0033），已有有效公开链接的来源不能建立官方绑定。否则官方取得
的内容会被转发给其他阅读器，官方 Folo 也可能反过来订阅到自己的内容。

### 可见性

- 供给端的 provider 列表增加 `folo_official`，报告是否已关联、账号状态、绑定数量和最近错误。
- 核心在该 provider 可用时宣告能力 `sources.folo_official_acquisition`，与表示官方 SDK 接口的
  `rsshub.hosted` 无关，不启用任何官方 SDK 调用。
- 核心的获取诊断显示上游为官方接口；个人凭据总览（5A.10）把已绑定来源报告为使用“官方 Folo 账号”。

### 调用官方接口的准则

- 只调用固定的少数接口（会话校验、订阅读取/创建/删除、Feed 查询、Entry 列表），以允许清单约束并由测试
  保证。
- 使用如实标识自己的 User-Agent，不伪装成官方客户端，不规避官方的限流、额度或校验。官方拒绝此类访问时，
  本能力停用，而不是绕过。
- 官方 API 地址是部署配置；未配置时整个能力不存在，行为与阶段 5A 完全相同。
- 可为官方接口单独配置出站代理：中国大陆的节点直连官方 API 不通。

## 对主方案的修订

- 主方案“Feed 获取提供方配置”中的获取关系字段保存在供给端数据库，以逻辑地址为键，不含
  `local_subscription_id`。
- `entry_provider_mappings`、`entry_duplicate_candidates`、`entry_provider_conflicts`、切换后的七天重叠
  拉取、按错误类型自动降级和二十四小时授权恢复窗口全部推迟到后续切片。
- 主方案中“先接 RSSHub 路由目录与发现能力”的顺序调整为先接托管获取：自有路由目录（ADR-0028）已经覆盖
  发现表单，当前缺的是获取能力。

## 未采用的方案

- **适配器放在核心：** 核心会重新持有外部凭据并直接访问外部平台，违背 ADR-0025 和 ADR-0026。
- **为官方来源使用新的逻辑地址（如 `folo://`）：** 同一来源换提供方就变成另一个 Feed，订阅、已读和评估
  历史都会断开。
- **客户端同时连接官方和自有后端：** 主方案已否决；鉴权、资源身份和故障回退会扩散到每个调用点。
- **整账号同步官方订阅和 Entry：** 超出按 Feed 授权的范围，并让官方成为事实上的主数据来源。
- **供给端保存官方 Entry 并自行物化：** 官方已经保存这些 Entry，重复保存只增加状态和迁移成本；按需渲染
  加缓存足以满足核心的轮询。
- **官方失败时自动回退自建 RSSHub：** 两个提供方的 GUID 和缓存窗口是否一致尚未验证，自动切换可能产生
  重复 Entry 或来回抖动。
- **依赖 `@follow-app/client-sdk`：** 会把官方 SDK 及其依赖带入供给端的生产锁；第一刀只用到六个接口，
  用带严格校验的薄客户端更容易固定和审查。

## 影响

- 自建 RSSHub 抓不稳的来源可以逐个改由官方获取，核心、客户端和既有数据不变。
- 供给端首次持有一个第三方账号的会话凭据，它的泄露面等同于该官方账号。
- 影子订阅会占用官方账号的订阅额度，并在官方账号中累积未读；官方账号上配置的 Action 或 AI 功能可能对
  这些 Entry 生效并消耗官方额度。
- 官方客户端使用的接口不是对第三方承诺稳定的 API。接口变化会让该 provider 不可用，但不影响其他来源。

## 待验证

5B.0 已用所有者的官方账号验证，结果见实施计划的“5B.0 探查结果”。

已确认：

- 非官方客户端可以调用这些接口，不需要官方客户端专有的请求头。原否决条件写的是 Bearer 方式，实际只有
  会话 Cookie 有效；上文已相应修订。
- 服务条款由所有者判断，所有者已于 2026-10-04 确认继续。
- 会话有效期为 30 天；Entry 列表按 Feed 返回完整正文，单页上限 100；`free` 套餐不能创建私有订阅，
  RSSHub 订阅额度为 30。

仍待验证，不阻塞接管已有订阅的路径：

- 会话是否滚动续期。
- 同一路由经官方与自建 RSSHub 取得的 GUID 是否相同。
- 影子订阅的创建与删除往返，以及开启两步验证时是否需要验证码。
- 官方限流和额度拒绝的响应形状。
